# 🦶 Machine Learning Based Burning Feet Syndrome Symptom Assessment

An end-to-end academic Machine Learning project (B.Tech Computer Science) that builds a
multi-class classifier to produce a **preliminary, ML-based symptom-assessment category**
(`Low` / `Moderate` / `High`) from symptom and health-history inputs, served through a
Streamlit web application.

> ⚠️ **Medical Disclaimer:** This project does **not** diagnose Burning Feet Syndrome. It is
> trained entirely on a **synthetic/demonstration dataset** created for academic purposes.
> The output is a preliminary, ML-based pattern classification — **not** a clinical diagnosis.
> Always consult a qualified healthcare professional for real symptoms.

---

## Project Overview

Burning Feet Syndrome describes sensations (burning, tingling, numbness, pain) in the feet,
often discussed alongside factors like diabetes, vitamin deficiency, thyroid conditions,
alcohol use, and peripheral neuropathy. This project demonstrates a full applied-ML workflow —
from synthetic data generation through EDA, feature engineering, model comparison,
hyperparameter tuning, explainability, and deployment — wrapped in a simple Streamlit UI.

## Problem Statement

Given a set of self-reported symptoms and health-history factors, predict a preliminary
severity-pattern category (Low / Moderate / High) that a user's inputs most resemble, based on
patterns learned from a synthetic training dataset.

## Objectives

- Build a clean, reproducible ML pipeline (data → preprocessing → model → app).
- Compare multiple classification algorithms fairly and pick the best on measured performance.
- Apply hyperparameter tuning to the strongest candidate.
- Provide a simple, explainable Streamlit interface for demonstration.
- Clearly communicate that this is an academic project, not a diagnostic tool.

## Dataset

- **File:** `data/burning_feet_dataset.csv`
- **Type:** Synthetic / Demonstration dataset (~1500 records), generated by `generate_dataset.py`
  using randomized, internally-consistent rules (e.g., diabetes and neuropathy history increase
  the probability of burning/tingling/numbness symptoms and higher severity).
- **Target:** `assessment` — `Low`, `Moderate`, `High` (an academic/demo classification target).

### Features

| Category | Features |
|---|---|
| Personal | `age`, `gender` |
| Symptoms | `burning_sensation`, `tingling`, `numbness`, `foot_pain`, `warmth_sensation`, `redness`, `swelling`, `night_time_symptoms`, `duration_weeks`, `severity_level` |
| Health History | `diabetes_history`, `vitamin_deficiency_history`, `thyroid_condition`, `alcohol_risk_factor`, `peripheral_neuropathy_history` |
| Lifestyle | `physical_activity` |
| Engineered | `symptom_score`, `risk_factor_count`, `duration_category` |

## ML Algorithms Compared

1. Logistic Regression
2. Decision Tree
3. Random Forest
4. K-Nearest Neighbors (KNN)
5. Support Vector Machine (SVM)

All models are wrapped in a single `sklearn.Pipeline` (`ColumnTransformer` preprocessing +
classifier) to prevent data leakage, evaluated with stratified 5-fold cross-validation and a
held-out test set, and compared on Accuracy, Precision, Recall, and F1-score (macro-averaged).

## Methodology

```
Dataset → Data Cleaning → EDA → Visualization → Feature Engineering → Encoding
   → Train-Test Split → Feature Scaling → Multiple ML Models → Evaluation
   → Best Model Selection (by measured F1) → Hyperparameter Tuning (GridSearchCV)
   → Model Saving (joblib) → Streamlit App → User Input → Prediction → Result Visualization
```

## Model Evaluation & Results

On the latest run (see `reports/model_comparison.csv` for exact numbers, which will vary
slightly if you regenerate the dataset with a different seed):

| Model | Accuracy | Precision | Recall | F1 Score |
|---|---:|---:|---:|---:|
| SVM (tuned) | ~0.87 | ~0.87 | ~0.87 | ~0.87 |
| Logistic Regression | ~0.87 | ~0.87 | ~0.87 | ~0.87 |
| Random Forest | ~0.86 | ~0.86 | ~0.86 | ~0.86 |
| Decision Tree | ~0.81 | ~0.80 | ~0.81 | ~0.80 |
| KNN | ~0.78 | ~0.80 | ~0.77 | ~0.78 |

The final model in this run was a **tuned SVM** (`GridSearchCV` over `C`, `kernel`, `gamma`),
selected because it had the highest macro F1-score on the held-out test set — not assumed in
advance. Because SVM has no native `feature_importances_`, the project uses **permutation
importance** for explainability.

*These numbers reflect performance on synthetic data only and make no claim of clinical
accuracy.*

## Streamlit Application

`app.py` provides:
- A symptom/health-history input form (checkboxes, radios, sliders, selectboxes).
- A clear academic disclaimer.
- A preliminary assessment result with a class-probability bar chart.
- A summary of key symptoms/health factors entered.
- A model-explainability section (top features driving the model's predictions).

## Installation & How to Run (VS Code)

### 1. Prerequisites
- Python 3.10+ installed
- VS Code with the **Python extension** installed

### 2. Open the project in VS Code
```bash
cd burning-feet-ml
code .
```

### 3. Create and activate a virtual environment
In the VS Code integrated terminal (View → Terminal):

**Windows (PowerShell):**
```powershell
python -m venv venv
venv\Scripts\Activate.ps1
```

**macOS / Linux:**
```bash
python3 -m venv venv
source venv/bin/activate
```

In VS Code, select this venv as your interpreter: `Ctrl+Shift+P` → **"Python: Select Interpreter"**
→ choose `venv`.

### 4. Install dependencies
```bash
pip install -r requirements.txt
```

### 5. Generate the dataset (already included, but you can regenerate it)
```bash
python generate_dataset.py
```

### 6. Run EDA (optional — generates plots in `reports/figures/`)
```bash
python src/eda.py
```

### 7. Train all models, compare, tune, and save the final pipeline
```bash
python src/train_models.py
```
This creates `models/burning_feet_model.pkl`, `models/model_metadata.json`,
`reports/model_comparison.csv`, and `reports/feature_importance.csv`.

### 8. (Optional) Re-evaluate the saved model quickly
```bash
python src/evaluate_models.py
```

### 9. (Optional) Try a single prediction from the command line
```bash
python src/predict.py
```

### 10. Run the Jupyter notebook (optional, for full walkthrough / viva demo)
```bash
jupyter notebook notebooks/burning_feet_analysis.ipynb
```
Or open it directly inside VS Code (it supports `.ipynb` natively) and select the `venv` kernel.

### 11. Run the tests
```bash
pytest tests/test_prediction.py -v
```

### 12. Launch the Streamlit application
```bash
streamlit run app.py
```
This opens the app in your browser at `http://localhost:8501`.

## Deployment (Streamlit Community Cloud)

1. **Create a GitHub repository** (e.g., `burning-feet-ml`) and push this project:
   ```bash
   git init
   git add .
   git commit -m "Initial commit: Burning Feet Syndrome ML project"
   git branch -M main
   git remote add origin https://github.com/<your-username>/burning-feet-ml.git
   git push -u origin main
   ```
2. Ensure **`requirements.txt`** is present at the repo root (it already is).
3. Go to **[share.streamlit.io](https://share.streamlit.io)** (Streamlit Community Cloud) and
   sign in with GitHub.
4. Click **"New app"**.
5. **Connect** your GitHub account/repository if prompted.
6. Select:
   - **Repository:** `<your-username>/burning-feet-ml`
   - **Branch:** `main`
   - **Main file path:** `app.py`
7. Click **"Deploy"**. Streamlit Cloud will install `requirements.txt` and launch the app.
8. Once deployed, **verify** the app loads, the form submits, and predictions display correctly.
9. Note: make sure `models/burning_feet_model.pkl` is committed to the repo (it's a small file
   here) so the deployed app can load it without retraining.

### Updating the deployed app
Any time you push new commits to the connected branch (`main`), Streamlit Community Cloud
automatically redeploys:
```bash
git add .
git commit -m "Update model / app"
git push
```
You can also manually trigger a "Reboot app" from the Streamlit Cloud dashboard if needed.

## Testing

`tests/test_prediction.py` covers:
- Model file existence and loading
- Valid input → valid class prediction
- Probability outputs summing to ~1
- Minimum / maximum age edge cases
- High-risk and low-risk symptom combinations
- Missing required field (raises `KeyError`)
- Unknown/invalid categorical values (handled gracefully via `OneHotEncoder(handle_unknown="ignore")`)
- Feature-engineering correctness (`symptom_score`, `risk_factor_count`, `duration_category`)

Run with:
```bash
pytest tests/test_prediction.py -v
```

## Limitations

- The dataset is **entirely synthetic** — it does not reflect real patient data or verified
  clinical relationships, so performance metrics are not indicative of real-world diagnostic
  accuracy.
- The feature list is a simplified, illustrative set and does not capture the full clinical
  picture used by medical professionals.
- The model has not been validated against any real-world clinical outcomes.
- Class boundaries (Low/Moderate/High) are defined by a synthetic composite scoring rule, not
  by clinical consensus.

## Future Scope

- Replace synthetic data with properly consented, de-identified real-world data (with clinical
  supervision) if extending beyond an academic exercise.
- Add more granular symptom-severity questionnaires (e.g., validated neuropathy screening
  scales).
- Experiment with additional models (Gradient Boosting, XGBoost, Neural Networks).
- Add user accounts / history tracking (would require careful privacy handling).
- Deploy a REST API layer for integration into other academic tools.

This application is an **academic machine-learning project** and does **not** provide a medical
diagnosis. The prediction is based on a model trained on **synthetic data** and should not be
used as a substitute for professional medical advice, diagnosis, or treatment. If you are
experiencing real symptoms, please consult a qualified healthcare professional.
